# Rules and Judging Criteria

Everything here is a hard constraint. If a design choice conflicts with this file, this file wins.

## Deadline

**15 October 2026, 12:15 AM IST** (so effectively the end of 14 October). Submission is on Devpost.

## Data rules (breaking these means disqualification)

**Allowed as inputs:**

- Sentinel-1
- Sentinel-2
- Copernicus DEM
- OpenStreetMap as it was **before** the event (ohsome API snapshot, on or before 27 July 2026 for the Trishuli case)
- The listed training datasets: Kuro Siwo, Sen1Floods11

**Not allowed as inputs:**

- Copernicus EMS maps (including EMSR927)
- UNOSAT maps or any other published damage maps
- OpenStreetMap edits made after the event

The not-allowed sources may be used **only to check results**, never to produce them.

**Implication for the code:** do not pull in any other dataset as an input. That rules out common helpers such as global surface-water layers, population grids and other elevation models. Derive permanent water from the pre-event Sentinel-1 image, and estimate population from OpenStreetMap building counts. Keep validation code (which reads EMSR927) in a clearly separate module that the pipeline never imports.

## Functional rules

- The system must run end to end from raw satellite data for **any area and date the judges choose**. Nothing may be hardcoded to the Trishuli corridor.
- For Sentinel-1 change detection, compare before and after images from the **same orbit track**.
- In the copilot, every number must come from the system's own maps and computed data. The language model must never invent a figure.
- Situation reports must be available in **English and Nepali**.
- Do not use images of victims anywhere.
- Present the system as an educational prototype, not an operational tool.

## Required attribution (must appear in every submission)

Put these in the README, the report and the dashboard footer:

- "Contains modified Copernicus Sentinel data 2026."
- "Produced using Copernicus WorldDEM-30 © DLR e.V. 2010–2014 and © Airbus Defence and Space GmbH 2014–2018 provided under COPERNICUS by the European Union and ESA; all rights reserved."
- "© OpenStreetMap contributors."
- A citation for any training dataset used:
  - Kuro Siwo: Bountos et al., 2024 (NeurIPS 2024)
  - Sen1Floods11: Bonafilia et al., CVPR Workshops 2020
- When EMSR927 is used for checking: "European Union, Copernicus Emergency Management Service data"

Licence notes: OpenStreetMap data is ODbL, so a modified version of the OSM data itself, if published, must stay under ODbL.

## Judging criteria (Track B)

Evaluation is **live, on areas and dates chosen by the judges on the day**.

| Criterion | Weight |
|---|---|
| Flood and damage mapping quality | 30% |
| AI component | 25% |
| Cut-off settlement analysis | 20% |
| Report, understanding in Q&A, and honesty about limitations | 15% |
| Dashboard and situation report usability | 10% |

## Deliverables checklist (Track B)

- [ ] Map dashboard
- [ ] One-page situation report generated by the system
- [ ] Public GitHub repository with a README explaining how to run the system
- [ ] Report, max. 6 pages, including a limitations section
- [ ] 3-minute demo video
- [ ] Required data attributions and training-dataset citations
- [ ] Case-study results compared with the EMSR927 reference maps

## Devpost submission requirements (all tracks)

- [ ] Project description: what was built, the problem it solves, how it works
- [ ] Link to a public GitHub repository. The README must include setup instructions, prerequisites and dependencies, and instructions for running the project.
- [ ] Demo video on YouTube. The general guideline says 3 to 10 minutes; Track B's own checklist says 3 minutes, so aim for 3. Unlisted is fine, private is not. It must show the project running and explain the approach. English audio or English subtitles are required.
- [ ] Team information: every member under their real full name, each with a Devpost account, each added to the submission

## Hackathon-wide rules

- Team size is 1 to 4. One team submits in one track only, and a person can be on only one submitting team.
- AI coding assistants are allowed, but must be disclosed: list the AI tools in "Built With" on Devpost, and note in the README which parts of the project were AI-assisted. Undisclosed use is treated as misrepresentation.
- Team members must be able to explain how the code works if a judge asks.
